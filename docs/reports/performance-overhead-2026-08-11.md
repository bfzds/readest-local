# 性能开销分析（2026-08-11）

## 结论

运行时开销属于“正常偏大”的桌面阅读器：日常读 EPUB 不重，但内存占用会比较明显，因为界面跑在系统 WebView2（Edge Chromium）里。开发/构建开销才是真正的大头。

## 架构

- Tauri 2 + Next.js 16 / React 19，Rust 负责本地解析、封面、数据库。
- 前端用 foliate-js 渲染 EPUB，PDF 走 PDF.js，中文相关能力用 WASM（simplecc、jieba）。
- 书库与全文搜索用 Turso/SQLite（Tantivy 等方案）。

## 实测体积（本机）

- 便携版可执行文件：52.1 MB（前端资源已内嵌）。
- 便携版总目录：91.4 MB，其中用户书库约 39.3 MB，应用本体约 52.1 MB。
- 生产静态导出 `out/`：约 47.7 MB；最大单个 JS chunk 约 0.47 MB。
- 根 `node_modules`：约 1.9 GB。
- `target/` 构建缓存：约 23 GB。
- `.next/` 构建缓存：约 3.9 GB。

## 运行时评估

- Tauri 壳本身很轻，但 WebView2 每开一个窗口都会带浏览器进程，空闲内存通常也要一两百 MB 以上；多窗口会更高。
- 读纯文本/EPUB 的 CPU 压力不大；PDF.js 渲染、词典查询、TTS、大书库全文搜索会明显升高 CPU 和内存。
- 仓库自带基准显示：1000 本书的缺失词全库扫描约 4.8 秒，100 本混合书约 0.48 秒；常见词查询在毫秒级。搜索属于可用但不算极致。
- 本次未实际启动应用，内存数字为架构估算；如需精确值，可在运行 readest-local.exe 后用任务管理器或脚本测量。
